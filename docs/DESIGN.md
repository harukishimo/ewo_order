# V01 — Atelier / あなたの暮らしに、一枚の絵。

## 方針

美術館のキャプションと、小さなアトリエの親しみやすさを合わせる。顧客には「作品を相談して制作依頼する」体験、管理者には「次に取りかかる作品がわかる」道具を提供する。商品イメージは抽象的な色面の作品例でよい。外部画像や有料フォントは必須にしない。イメージは「作品イメージ」と表示し実在商品との混同を防ぐ。

## Uへ：顧客画面

### 共通ヘッダー / トップ

左にロゴ「Atelier」と小さく「オーダーペインティング」、右に「注文一覧」「絵を相談する」。ヘッダー高さ80px、モバイルはロゴと注文一覧に絞る。トップは左右2列：左に小さな英字「ART, MADE FOR YOU」、大見出し「あなたの暮らしに、\n一枚の絵。」、説明、主CTA「絵を相談する」。右は額縁を模した作品イメージ。次に3つのサイズカードと「相談 → 内容を確認 → 制作依頼」の手順。価格付近へ常に「デモ料金・決済は行いません」。

### ログイン

幅440px以内のフォーム。「相談のつづきを、ここから。」の見出し、実際の認証方式に合う説明。メール等のラベルはプレースホルダーで代替しない。送信中状態と送信結果を同じカード内に出す。デモ動線と実認証の動線は文言で明確にする。

### 相談

ページ名「絵の相談」、補助「想いを聞かせてください。一緒に条件を整えていきます。」。デスクトップは左会話（約65%）、右「ご希望の一枚」条件カード。会話はアプリ側を紙色、顧客側を薄緑、最大幅85%、送信者名も付ける。下部入力はtextareaと「送信」。Enterは改行、Ctrl/⌘+Enterで送信（日本語IME変換中は送信禁止）。候補は「候補」とラベルし、ボタンで確認後に条件へ反映する。

条件カードはサイズ、テイスト、予算、希望日、補足の順。未入力は「未指定」、回答済みの予算なしは「予算指定なし」、日付なしは「希望日なし」。各入力は直接編集できる。「AI判定の候補」と「確認済み」を混同しない。サイズボタンには寸法とデモ価格を併記。予算超過は「Mサイズは20,000円です。ご予算またはサイズを見直してください」と解決方法を表示。カスタム/その他は「個別相談が必要です」とし、確定操作を出さない。

必要項目が揃ったら「見積もりを確認」。最終確認はインラインの独立カード。サイズ・テイスト・補足・価格・希望日・有効期限を再掲し、「希望日は納期の確約ではありません」「制作依頼の受付です。決済は行いません」を直前に表示。主ボタン「この内容で注文する」、副ボタン「内容を修正」。会話内の「はい」で注文しない。注文済みでは確認ボタンを置き換え、注文番号と詳細へのリンクを表示。

### 注文一覧 / 詳細

一覧はカード形式：注文番号・サイズ/テイスト・デモ価格・状態・受付日。詳細は「受付済み → 制作中 → 制作完了」の文字付き進捗と確定した仕様。要確認/取消は専用状態文を表示し、通常の進捗から誤解なく分離する。希望日は「希望日（未確約）」と表示する。

## Aへ：管理者画面

ヘッダーに「Atelier / 制作管理」、顧客画面リンク。見出し「制作ボード」、説明「次に描く一枚を、ここから。」。件数カードは「制作待ち」「制作中」「要確認」「評価待ち」。その下に状態フィルター。要確認・評価待ちを独立セクションで必ず見つけられるようにし、通常キューの底へ埋めない。

制作可能一覧は優先度順。列は優先度（数値＋ラベル）/注文・作品条件/希望日/状態/詳細リンク。補足を無制限に表示せず詳細へ。手動優先度に「手動設定」、未評価に「評価待ち」を添え、失敗を0点として扱わない。確信度の横に「モデルの確信度。正解率ではありません」。

詳細は左に仕様・補足、右に制作状態と操作。状態に応じた主CTAを一つ（「制作を開始」「制作を完了」）にする。取消は副領域で対象注文を再確認。優先度はスコア、緊急性・希望日・待機日数の内訳、複雑度を分けて表示。「優先度を変更」には0〜100と必須理由、解除操作。評価待ち/失敗には「再評価する」。下部に変更日時・操作・変更者・理由の履歴。

## 共通状態とアクセシビリティ

- 読込中：対象領域に「読み込み中…」。送信中はボタン「送信中…」とdisabled。入力済み本文は成功するまで消さない。
- 空：注文は「まだ注文はありません」＋「絵を相談する」。制作一覧は「この条件の制作タスクはありません」。不具合と空を混同しない。
- 失敗：入力近くの`role=alert`に原因と再試行手段。ネットワーク失敗で会話や条件を消さない。409なら「内容が更新されました。最新の条件を確認してください」。
- Jev障害：「判定を利用できません。下の項目を選んで相談を続けられます。」。フォームを利用可能なままにする。
- モック：常に見える小バナー「デモ判定 · 実際のJevには接続していません」。永続化がデモの場合は、その保存範囲も別途明示。
- ステータスは色＋日本語テキスト。タッチ領域44px以上。入力にlabelとエラーのaria-describedby、ページに単一h1。
- 新規返信のみ`aria-live=polite`、会話ログ全体を毎回読み上げない。順序は会話→条件→確認。キーボードで全操作可能。
- 動きは控えめ、prefers-reduced-motionに従う。レスポンシブ境界768pxで1列。モバイルは条件カードを会話の上でdetails展開、要確認と価格は閉じても見える。ページ横スクロール禁止。管理者表はモバイルでラベル付きカードへ。
